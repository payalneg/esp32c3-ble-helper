# VESC BLE Helper

[English](README.md) | **Русский**

Маленькая плата на ESP32-C3, которая связывает **спящие BLE-гаджеты** —
кнопки-брелоки (камера-шаттеры), медиакнопки, BLE-датчик каденса — с
**контроллером VESC по CAN-шине**.

```
[HID-брелоки ×3]────BLE──┐                              CAN 500k
[Каденс-сенсор]─────BLE──┼── ESP32-C3 ── TWAI ──[TJA1051]────── VESC (main.lisp)
[GUI / Android app]─BLE──┘   NUS-мост + конфиг-сервис + OTA         │
                                                              [дисплей P4]*
                                                              * опционально
```

Что умеет:

* **Кнопки → CAN-команды.** Нажатие кнопки на любом привязанном брелоке —
  и помощник шлёт настроенный для неё CAN-кадр. LispBM-скрипт на VESC
  принимает кадр и действует: вкл/выкл газа, смена скоростного режима или
  что угодно, что вы напишете. Вся логика живёт в LISP — помощник лишь
  простой и надёжный мост.
* **Педальный ассист (PAS).** Читает BLE-датчик каденса
  ([payalneg/cadence-for-ebike](https://github.com/payalneg/cadence-for-ebike))
  и 20 раз в секунду шлёт арбитру на VESC уставку тока с рампами, за которой
  стоит тройная цепочка watchdog'ов.
* **Мост для VESC Tool.** Подключаете VESC Tool по BLE (Nordic UART) — и
  настраиваете сам VESC через помощника: пакеты прозрачно уходят в CAN.
* **Настройка по BLE.** Python-GUI (`tools/config_gui.py`): привязка
  устройств, тюнинг PAS, команды кнопок, обновление прошивки по воздуху.
  Будущее Android-приложение использует тот же GATT-протокол.

Ядро CAN/BLE/PAS портировано из проекта
[esp32p4-android-auto](../work/esp32p4-android-auto) (ветка `pas-system`);
`lisp/main.lisp` — скрипт управления мотором из того же проекта с
добавленной обработкой команд помощника.

## Железо

| Компонент | Примечания |
|---|---|
| **Плата ESP32-C3** | 4 МБ flash, PSRAM не нужен. Пины по умолчанию = как у VESC Express (GPIO0/1). На стоковом Seeed XIAO ESP32-C3 GPIO0/1 **не выведены** — используйте D4/D5 (см. ниже). |
| **CAN-трансивер** | Рекомендуется **TJA1051T/3** (вариант с VIO). SN65HVD230 (нативные 3.3 В) тоже подходит. |
| **Питание** | 5 В на трансивер; плата ESP — от своего 5 В/USB. Земля общая с VESC. |

### Распиновка (пины по умолчанию — как у VESC Express)

```
ESP32-C3                TJA1051T/3                    VESC / шина
─────────               ──────────                    ───────────
GPIO1  (CAN TX) ───────► TXD
GPIO0  (CAN RX) ◄─────── RXD
3V3     ───────────────► VIO   (опора логических уровней)
5V      ───────────────► VCC
GND     ───────────────► GND
                         S ────► GND  (silent-режим ВЫКЛ)
                         CANH ───────────────────────► CANH
                         CANL ───────────────────────► CANL
```

* **TJA1051 без суффикса «/3»** (и распространённые синие модули TJA1050) —
  это 5-вольтовая логика: RXD выдаёт 5 В, а ESP32-C3 **не 5V-tolerant**.
  Ставьте делитель на RXD (например 1 кΩ / 2 кΩ) или берите вариант /3
  с VIO.
* **Терминация:** CAN-шине нужны 120 Ω на обоих физических концах. Если
  помощник — крайний узел, резистор обязателен.
* GPIO0/GPIO1 на C3 безопасны для CAN — страппинг-пины у него 2/8/9.

### Альтернативные пины (стоковый XIAO ESP32-C3)

GPIO0/1 на XIAO не выведены. Настраивается в `idf.py menuconfig → VESC CAN`:

| Сигнал | Пин XIAO | GPIO |
|---|---|---|
| CAN TX | D5 | GPIO7 |
| CAN RX | D4 | GPIO6 |

### CAN-идентификаторы по умолчанию

| Узел | ID |
|---|---|
| Ходовой VESC | **10** |
| Помощник (это устройство) | **3** |
| Дисплей P4 (если есть) | 2 |

Скорость 500 кбит/с. ID и скорость (125/250/500/1000) меняются в GUI и
хранятся в NVS.

## Сборка и прошивка

ESP-IDF v5.5+:

```bash
source ~/.espressif/v5.5.3/esp-idf/export.sh
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/tty.usbmodem* flash monitor     # первая прошивка по USB
```

Дальнейшие обновления — **по BLE** из GUI (вкладка Firmware, файл
`build/esp32c3_ble_helper.bin`).

## Первичная настройка

```bash
pip install bleak
python3 tools/config_gui.py
```

1. **Connect** — GUI находит устройство с именем `VESC-BLE-Helper`.
2. **Вкладка LISP** — загрузите `lisp/main.lisp` на VESC (идёт через
   NUS-мост протоколом VESC Tool). Этот скрипт владеет мотором: арбитр
   газ/тормоз/круиз/PAS + обработка команд помощника.
3. **Вкладка Binding** — «Scan for button», нажмите кнопку на брелоке,
   чтобы он проснулся, выберите в списке, «Bind selected». Повторите для
   остальных брелоков (до 3). Так же привязывается каденс-сенсор
   (крутните шатун, чтобы разбудить).
4. **Нажмите каждую кнопку по разу.** Кнопки распознаются по сигнатуре
   нажатия: первая нажатая в жизни становится **A**, следующая — **B**, …
   (до H, сквозь все брелоки). Смотрите вкладку Status.
5. **Вкладка Parameters** — проверьте CAN-команды кнопок (дефолты ниже),
   тюнинг PAS, ID/скорость шины. «Write» сохраняет всё в NVS.

Привязки, бонды, выученные кнопки и параметры переживают перезагрузку;
брелоки и сенсор переподключаются сами, как только просыпаются.

## Команды кнопок

Каждое нажатие передаёт настроенный CAN-кадр (hex ID + до 8 байт данных).
Кадры со стандартным 11-битным ID невидимы для протокола VESC и попадают
прямо в LISP-скрипт через `event-can-sid`.

Дефолты (совпадают с `lisp/main.lisp`):

| Кнопка | Кадр | Действие в `main.lisp` |
|---|---|---|
| A | id `123`, data `0001` | вкл/выкл ручки газа (master switch) |
| B | id `123`, data `0002` | смена скоростного профиля (бип на каждый) |
| C… | id `123`, data `0003`… | печатается — добавьте своё в `proc-helper-btn` |

Команда — это данные кадра, прочитанные как big-endian u16. Чтобы добавить
действие, расширьте `cond` в `proc-helper-btn`:

```lisp
((= cmd 3) (activate-cruise-control))   ; пример: кнопка C = круиз
```

Отдельный минимальный приёмник — `lisp/can_button_skeleton.lisp`;
минимальный скрипт «только вкл/выкл газа» — `lisp/throttle_toggle.lisp`.

## Педальный ассист

`pas.c` превращает каденс в уставку тока: режимы SWITCH (фиксированный ток
уровня) и PROPORTIONAL (растёт с каденсом), уровни ассиста, задержка
старта, стартовый «пинок», рампа А/с, задержка стопа. Уставка уходит
арбитру кадром `'VP' 0x05` 20 раз в секунду.

Цепочка безопасности (каждый слой сваливается в накат):

1. Нет нотификаций от сенсора 600 мс → каденс считается нулевым.
2. Нет свежей уставки 400 мс → помощник шлёт один `0` и замолкает.
3. LISP: уставка старше 0.4 с → накат.
4. Скрипт умер → `app-disable-output` истекает за 1.5 с, штатная ручка
   возвращается, мотор глохнет по command-timeout.

## BLE-интерфейс (для разработчиков приложения)

Имя в эфире `VESC-BLE-Helper`; в advertising лежит UUID NUS (чтобы VESC
Tool находил устройство), имя — в scan response.

| Сервис | UUID | Назначение |
|---|---|---|
| Nordic UART | `6e400001-b5a3-f393-e0a9-e50e24dcca9e` | прозрачный мост VESC Tool ↔ CAN |
| Config | `ab1e0001-b1e5-4e15-8ac3-5e00c0de15b7` | всё остальное |

Характеристики конфиг-сервиса (`…0002`–`…0006`): CTRL (команды + ответы),
STATUS (~2 Гц + мгновенно при нажатии кнопки), SCAN (поток результатов
сканирования), OTA-CTRL / OTA-DATA (обновление прошивки, потоковая запись
во флеш). Полные форматы кадров — в
[`main/ble_cfg_svc.h`](main/ble_cfg_svc.h).

## Совместная шина с дисплеем P4

* Источник PAS-уставки на шине — ровно **один**: если дисплей прошит
  `pas-system`, выключите его встроенный PAS.
* У всех узлов уникальные controller ID.
* Состояние выключателя газа живёт на VESC — его могут переключать и
  тачскрин дисплея, и кнопки помощника; последний выигрывает.

## Структура проекта

```
main/                   приложение прошивки
  ble_host.c            NimBLE dual-role, advertising
  ble_central_mgr.c     один общий whitelist-connect на все central-линки
  ble_hid_client.c      HOGP-хост, ×3 брелока, кнопки по сигнатурам
  ble_cadence_client.c  клиент каденс-сенсора (кастомный сервис cad0000x)
  ble_nus.c             мост VESC Tool (Nordic UART ↔ CAN)
  ble_cfg_svc.c         конфиг-сервис GATT + маршрутизация OTA
  ble_ota.c             BLE OTA, потоковая запись во флеш (без PSRAM)
  pas.c                 цикл каденс → ток
  throttle_ctl.c        команды выключателя газа
  settings.c            NVS: id, скорость, брелоки, кнопки, кадры
components/vesc_can/    драйвер TWAI + протокол VESC + транспорт 'VP'
lisp/
  main.lisp             арбитр мотора на VESC + панель + команды помощника
  can_button_skeleton.lisp  минимальный приёмник команд
  throttle_toggle.lisp  минимальный пример вкл/выкл газа
tools/config_gui.py     конфигуратор на bleak + tkinter
```
